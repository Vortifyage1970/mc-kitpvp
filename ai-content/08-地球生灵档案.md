## 0. 先看懂「编号」

随机池在 `src/data/kitpvp/functions/skill/earth/random.mcfunction`：

```mc
scoreboard players set #pool_size kitpvp.game 72          # 必须等于下面 matches 行的条数
execute if score @s kitpvp.rng matches 71 run function kitpvp:summon/earth_atrain
```

- 池里 `matches N` 的 **N 是 0 基索引**；本档案的 **地球·N+1 是它的人类编号**。
  例：`matches 37` ↔ 地球·38 ↔ `earth_twinstar`；`matches 71` ↔ 地球·72 ↔ `earth_atrain`；`matches 72` ↔ 地球·73 ↔ `earth_babywhelp`。
- **现状：72 条，0..71 无空号**（`tools/check_pool.ps1` 的 编号唯一=True / 缺号=[] 就是这个意思）。
- ⚠ **代码里大量 summon 文件头注释的编号已经过期**（池子中途重排过）：`earth_mortar` 写"地球·70"实际是 **地球·61**、`earth_supporter_fast` 写"地球·71"实际 **地球·62**、`earth_dublinn` 写"地球·55"实际 **地球·48**。**一律以本表 §1 的池号为准**，注释只在同号时才可信。
- 加一只生灵要同步四处：`random.mcfunction` 的 `matches N` 一行、`#pool_size`、卡片 `kit/info/earth.mcfunction:15` 的长串名称、本档案 §1 + §2。
- 掷骰：连掷 3 轮、每轮 7 次拼成 0..2097151，再 `% #pool_size`。现在 72 份余数只差 8（`2097152 % 72 = 8`），相对偏差十万分之一，等于等概率；若只用 1 轮 7 位再看余数，编号靠前的会双倍概率。
- 现在一共 1057 个 `.mcfunction`；`debug/` 里还剩 28 个（清单见 §4）。

## 2. 逐只说明（只写有内容可说的；总表里没提的按总表为准）
> ⚠ §2 各小节是不同时期写的，标题里的数字既不是池号也不是地球号（早期版本留下的），**只当标题看**；每只的确切编号一律查 §1。

### 2.1 早期 1–27 号

- **阴兵（1）**：`Invisible` 骷髅 + 锁链头盔，`PersistenceRequired:1b` 本局不自然消失；由幽灵职业的 advancement 触发（`@s` = 被攻击者），函数里不能再 `at @s`，否则阴兵会出现在使用者身边。
- **炮台（2）**：与里·弓箭手炮台同款弓骷髅，但不打主人；`turret_from_molten` 可把它转成熔火形态（喷火、30 秒后复原）。
- **iLsacuL（3）**：一只 20 血的猪。职业侧的计时器（`li/timer`）每 12 秒一圈：第 3 秒每只原地生一只 200 血复制体（选择器只取已存在的，不会同刻套娃）、第 6 秒每只半径 5 自爆并召一只「李朱俊泽」苦力怕、第 12 秒数一遍，≥14 只就开每刻自爆。魂石那只带抗性 V，炸不死，只能显式 kill。
- **Sheepass（4）**：普通羊，`sheep_aura` 每 10 秒给 20 格内玩家 20 秒反胃。
- **板砖哥（5/6）**：同一套外观（砖块头 + 手持砖块），分成击退 X / 火焰附加 II 两版；骷髅手里有物品就不会用弓，所以是近战。
- **斧头哥（7）**：南瓜头 + 金斧（金斧不带附魔，伤害全靠原版），生命上限 25。
- **宇航员（9）**：白色染色玻璃头，跳跃提升 X + 缓降。
- **大炸弹（10）/ 跟踪炸弹（11）**：`ignited:1b,Fuse:10s` 与 `Fuse:120s`；跟踪版把隐形小僵尸放进苦力怕的 `Passengers`（上下位：苦力怕外层）。
- **MC石头（12）**：石头头 + 石头武器，缓慢 IV + 抗性 III。
- **超凡升天（15/20）**：3 秒后漂浮 V 15 秒、再 15 秒清除；20 号是南瓜头 + 金斧 + 40 血的强化版。 两个**共用池号 14**（`earth_ascend_pick` 五五开），各占 1/2。
- **水星（16）**：青色皮革 + 石剑，常态 +0.2 移速（加法修饰符），本体 10 血（`max_health` 一起压到 10，血条才显示 10/10）。
- **扰动者（17）**：侦测器头 + 红火把，**12 血**；每 3 秒对 11 格内玩家发动「太阳耀斑」的中招效果。
- **渔夫（18/19）**：溺尸骑海豚 / 海龟，三叉戟 + 海晶灯（砖块）头，15 血。

### 2.9 迫击炮（70）

- **组成**：一只不能动、不能捡东西的僵尸（`NoAI:1b`、`movement_speed 0`、24 血、铁胸铁裤铁靴 + **投掷器**头），显示名「迫击炮」。它本身不近战，只负责按 3 秒一发的节奏往人身上扔鱼弹。
- **四个文件**：`summon/earth_mortar.mcfunction`（召本体，末行把 `earth_cd_a` 设 40 让首发别等太久）、`skill/earth/mortar_tick.mcfunction`（挑目标 + 开炮）、`skill/earth/mortar_fire.mcfunction`（锁定落点、召鱼弹、按距离装药）、`skill/earth/mortar_shell_tick.mcfunction`（鱼弹每刻的位移与引爆）。
- **索敌**：15 格内、活着的、**不是主人**的玩家。创造 / 旁观 / 带 `kitpvp.spectator` tag 的一律不算。有主人（`earth_owner ≥ 1`）时排除主人；**没有主人**（直接 `/function` 召、魂石召，`earth_owner` 是 0）时认不出召唤者，退化成“打范围内所有生存玩家” —— 手动测炮时它会打你自己，这是预期，不是 bug。
- **落点**：开炮那一刻在目标脚下放一个 `kitpvp.mo_aim` 的 marker，之后不再追人。所以玩家跑开就躲得掉，这才像迫击炮。
- **弹道**：`mo_vy` 是竖直初速（每刻 -1，按 0.95/0.8/0.65/…/-0.95 的分档表升降），`mo_hs` 是水平速度 ×100（按 15/27/36/45/50/53/55 分七档，对应 ≈3 / 4.5 / 7 / 10 / 13 / 16 / 19 格的中距）。滞空 = `2 × vy` 刻，水平总行程 = 滞空 × `hs`/100。
- **两个必须记住的写法**：
  1. **每个 `tp` 前都要 `at @s`**。函数里的 `~` / `^` 取的是“函数开始那一刻”的坐标快照，上一行刚把鱼挪走，下一行照样按旧坐标算，会把鱼拽回炮口 —— 表现是“鱼只升不横移、贴着头顶飘”。
  2. **水平位移要用 `rotated ~ 0` 把俯仰压平**再 `tp @s ^ ^ ^step`。不压平的话 `^` 顺着“鱼看落点”的视线往下斜，竖直分量吃掉一截水平行程，落点会系统性偏近 2–3 格。
- **引爆**三种：离落点 2 格内（三维距离）、**所在方块不是空气**（打墙、打地、打树都炸）、满 46 刻强制炸（这个上限必须大于最远一档的滞空 36 刻，否则远弹会在半空自爆）。
- **伤害**：3.5 格内 4 点（2 颗心）`minecraft:explosion`；有主人时跳过主人。
- **踩过的坑**：
  1. `mo_owner / mo_vy / mo_hs / mo_life` 这四个计分项**必须在 `load.mcfunction` 里 `scoreboard objectives add`**，否则 `scoreboard players set` 只报一行错、静默忽略，`vy/hs` 全是 0，鱼堆在炮口不动（`load.mcfunction:192` 起）。
  2. 距离分档要**首尾重叠**（`3..6`、`6..9`…）并先写一组默认值。中间留缝的话，6.5 格这种小数距离一档都不匹配，`vy/hs` 保持 0，鱼直接原地往下掉。
  3. `mortar_fire` 里写的 `hs` 必须落在 `mortar_shell_tick` 的水平档区间里（1..21 / 22..31 / 32..41 / 42..47 / 48..51 / 52..54 / 55..）。只改一边，鱼就只会升、不会走。
  4. **别用 PowerShell 的 `Set-Content` 改 `.mcfunction`**：它会加 UTF-8 BOM，带 BOM 的函数整个不加载 —— 表现是“鱼弹完全不炸了”，而 lint 查不出来。

### 2.10 支援者·fast / slow（71 / 72）

- **组成**：头戴**刷怪笼**（`minecraft:spawner`）、手拿铁剑的骷髅，15 血，显示名「支援者」。它不在召唤点站着，而是从**召唤点正上方 30 格**砸下来。
- **两个独立编号**（用户要求能单独召，所以不再共用 71 号）：
  - 地球·71 → 池号 70 → `summon/earth_supporter_fast.mcfunction`：裸降，没有药水、也**不加无敌**，30 格自由落体约 28 点摔落伤害 > 15 血 ⇒ 落地即死，纯粹是砸场子的。
  - 地球·72 → 池号 71 → `summon/earth_supporter_slow.mcfunction`：同一套配置，提起前灌 `slow_falling 1200 刻（60 秒）`，慢慢飘下来。60 秒是为了撑满 30 格（缓降约 0.7 格/秒）；它**带 `Invulnerable:1b`**，落地两刻后由 `supporter_land` 解除，落地后是一只正常的骷髅战士。
  - 随机池里两条各占一个号，所以随机召唤时仍然是一半一半。
- **三个文件（两个亚型共用后面两个）**：`earth_supporter_fast` / `earth_supporter_slow`（在地面召本体、缓降型上药、初始化 `sup_land`）；`skill/earth/supporter_lift.mcfunction`（`tp @s ~ ~30 ~`、挂 `sup_falling`）；`skill/earth/supporter_land.mcfunction`（踩到地面后播尘埃、收无敌）。
- **为什么先在地面召、下一刻才提上去**：`link.mcfunction` 只认领 4 格以内的 `earth_minion_new`（分配队伍 + 写 `earth_owner`）。直接在 30 格高召，它拿不到归属，落地后就是"谁靠近打谁"，连召唤者一起打。
- **为什么 slow 的下落段要 `Invulnerable:1b`、且落地后等两刻才收**：30 格的摔落伤害会把 15 血摔死，而命令先跑、实体后 tick，落地那一帧的伤害还没结算，立刻收无敌照样摔死，所以 `supporter_land` 先 `sup_land +1`，第 2 刻才 `data merge entity @s {Invulnerable:0b}`。fast 故意不要这层保护 —— 它就是要摔死的那个。
- **已知限制**：落点固定在召唤点正上方，玩家走开就砸不到。fast 落地即死、不造成任何伤害（只是个视觉冲击力）；slow 飘得慢，落到一半药效到点会转成正常下落（仍无敌，不会摔死）。

### 2.11 低空飞行器（73）

- **组成**：一只**普通蝙蝠**（原版 AI，不改高度、不悬停、不俯冲）当"吊车"，抗性 V + 虚弱 X，下面用 `Leash` 吊一只弓骷髅（白羊毛头、摔落保护 20 的皮靴、`NoGravity`、**12 血**）。沿用"分两帧召 + UUID 重试"的骨架（69 号飞行器已删，这套写法保留在这里），但出生点就在召唤者脚边（`~ ~1 ~`），不在高空。
- **五个文件**：`summon/earth_lowflyer.mcfunction`（清场 + 留 marker + 给召唤者打 `kitpvp.lf_owner_tmp` tag + 记队槽）、`summon/earth_lowflyer_a.mcfunction`（每刻重试召蝙蝠、上抗性/虚弱、按召唤者 tag 把蝙蝠并进 `earth_1..6`、排程吊舱）、`summon/earth_lowflyer_b.mcfunction`（召骷髅吊舱、抄蝙蝠的队与 `earth_owner`）、`skill/earth/lowflyer_tick.mcfunction`（共生 / 补绳 / 选靶 / 俯冲）、`tick.mcfunction` 一行调用。
- **蝙蝠吃不吃速度**：不吃。药水的 `speed` 改的是 `generic.movement_speed`，那是走路 AI 用的；蝙蝠/幻翼的飞行是另一套移动逻辑，而且这里俯冲是脚本 `tp`，跟速度完全无关。
- **抗性 V 的说明**：放大等级 4 = 抗性 V，伤害减免 100%，等于打不死。蝙蝠只有 6 血，不套这层它撑不过一箭；虚弱 X 只是让它自己那一口咬不掉人，真正的输出来自下面的骷髅。
- **共生**：骷髅吊舱没了，蝙蝠同刻 `kill`；出生那一帧用 `kitpvp.lf_spawning` tag 宽限（tag 不用 `/reload` 也存在，比计分安全）。
- **飞行**：完全交给原版蝙蝠 AI 和原版绳子，脚本一格都不挪。用户明确要求"就单纯拴起来，不要 tp"。只剩两件事：绳子断了接回去（`unless data entity @s Leash`），清掉断绳丢下的 lead 物品。
- **没靶子时**：朝召唤者慢慢靠（`distance=10..` 才动，每刻 0.35 格）。不这么做蝙蝠会自己乱飞、挂墙、钻洞，看起来像"飞走了"。
- **目标筛选 / 不打召唤者**：靠**队伍**。`random` 跑在 `summon.mcfunction` 的 `link` 之前，而 `link` 只认领"当刻已经存在"的生灵，蝙蝠要等下一帧才出生 ⇒ 永远不会被自动认领。所以 `earth_lowflyer` 自己先 `unless score @s kitpvp.etid matches 1..` 补跑一次 `link`（保证召唤者有队），再给召唤者打 `kitpvp.lf_owner_tmp`；`_a` 按"召唤者站在哪个 `earth_N`"把蝙蝠并队，`_b` 直接抄蝙蝠的队。**这条链不能依赖 `if score … matches 1..`**：没开局时 `kitpvp.etid` 不存在，`matches 1..` 静默为假，队伍一次都加不上（踩过：表现为实体无队伍、骷髅照打召唤者）。
- **已知限制**：原版绳超过约 10 格会自己脱手，之后就是一只普通蝙蝠 + 一只在地上跟着的骷髅（脚本每刻会把绳接回去，但接回去那一刻两者距离可能已经拉开）。蝙蝠会钻洞、挂墙，骷髅跟着进去就看不太到人。

### 2.12 罐子（74）与 小罐子（77）

- **本体**：一只**普通僵尸**，头戴 `minecraft:decorated_pot`（陶罐方块当头盔，和刷怪笼头、哭泣黑曜石头同一套"方块塞头槽"的做法），名字「罐子」，**6 血**，正常 AI，会走会打人。
- **小罐子**：`earth_jar_small` 是同款的 `IsBaby:1b` 版本 —— 跑得快、个子矮、砍起来更难瞄，`Health:6.0f` + `Base:6.0`（和大罐子一样脆）；死亡判定和摇号**完全共用**同一套代码，两个池号（73 / 76）行为一致。
- **死亡时**：`tick.mcfunction:391-395` 每刻先把罐子脚边 5 格内的 `kitpvp.earth_jar_guard` marker `tp` 到罐子身上，再 `unless entity @e[tag=kitpvp.earth_jar,distance=..3]` 判"罐子没了" → 调 `skill/earth/jar_pop`（开头 `playsound block.decorated_pot.break` + 一圈 poof 粒子）。自测入口 `/function kitpvp:debug/jar_test`：召一只无主罐子 → 2 秒后 `damage 100` → 报罐子 / 守卫 / 10 格内生灵数。
- **为什么用守卫 marker**：1.20.1 的数据包没有"死亡时"触发器；`Health:0.0f` 和 `DeathTime:1s` 两个写法都实测抓不到 —— 这个环境里实体被打死的当刻就整个不见了（木星在同一处踩过，`tick.mcfunction:321` 的注释写着）。守卫不依赖尸体的任何一帧，被砍死、被箭射死、被 `/kill`、被清场都会响。**自测别用 `/kill`**：它直接 `discard()`，实体当刻消失；用 `damage @s 100 minecraft:generic` 走真实受伤路径。
- **摇号**：直接 `function kitpvp:skill/earth/random`，和玩家召唤走**同一条链路**（同一个池、同一套 `#pool_size 76`），所以罐子里能蹦出包括另一只罐子在内的任何生灵。
- **owner 保留**（这是需求里特意点的一句）：先把罐子的 `earth_owner` 抄进临时分 `#jar_own`（`jar_pop` 的 `@s` 是守卫，所以这个分要从守卫身上读），召唤完再把 24 格内**刚出生且还没主人**的生灵（`kitpvp.earth_minion_new` + `scores={kitpvp.earth_owner=..0}`）设成同一个编号，并按 1..6 补 `team join earth_N`。**光写 `earth_owner` 不够**：不攻击召唤者靠的是同队，草丛 / 电磁炮那类才读分数。
- **为什么是 24 格不是 3 格**：支援者会在两刻后被提到 30 格，3 格半径够不着它。
- **reset 要封口**：`game/reset.mcfunction:61` 在 `kill @e[tag=kitpvp.earth_minion]` 之前先 `kill @e[tag=kitpvp.earth_jar_guard]` —— 和木星一样先杀守卫，终局不会让罐子集体"碎一次"刷怪。

### 2.13 蜂巢（75）

- **本体**：普通僵尸，头戴 `minecraft:beehive`（蜂巢方块当头盔），名字「蜂巢」，**15 血**，正常 AI。
- **判定**：`advancement kitpvp:player/hive_struck`（`player_hurt_entity` + `conditions.entity` 匹配 `type: zombie` 且 `Tags:["kitpvp.earth_hive"]`）。谁打的就触发给谁，奖励函数 `hive_struck` 先把 advancement 撤销再发东西，所以连击每一刀都算。
- **一次给几个**：**每下固定 3 张**（`hive_struck` 里连调三次 `hive_give`），不再按挨打次数递增。
- **给谁**：**只给打它的那名玩家**。advancement 由被打的那一下触发、奖励函数以"出手的人"身份执行，旁边的人不沾；创造/旁观/召唤者都不会触发（advancement 只在真打到时才会给）。
- **"眩晕"是什么**：`minecraft:blue_dye` + 自定义名「眩晕」（青色、不斜体）+ 耐久 I + `kitpvp.serial`。
- **为什么不用 `give`**：`give` 出去的物品 NBT 完全一样就会自己叠成一摞，看不出"这一下给了几个"。照搬 COSER 的「物料」做法——掉一个物品实体、当场写唯一序号；`PickupDelay:0s` 让它下一刻就被贴身捡走，体感等于直接塞进背包。
- **序号来源**：全局 `#hive_serial`（存在 `kitpvp.game` 上，不需要新计分项），每次 +1 后 `store result` 写进物品的 `Item.tag.kitpvp.serial`，写完立刻摘 tag，所以连续三个也能各拿一个号。

### 2.20 飞龙宝宝（地球·73 / `earth_babywhelp`）

- **火球故意不用原版物理**：`/summon minecraft:small_fireball ... {NoGravity:1b}` 并且**不给 Motion**，由 `babywhelp_ball` 每刻 `tp @s ^ ^ ^0.9` 推着飞。两个原因：① 原版小火球砸到方块会就地放火、而且**无视 mobGriefing**（[MC-70251](https://bugs-legacy.mojang.com/browse/MC-70251)），射偏一发竞技场就着一块；② 零速度时原版 `ProjectileUtil.getHitResultOnMoveVector` 的检测长度是 0，永远不会触发它自己的碰撞 ⇒ 既不放火也不会误伤。
- 火球是**每刻重新 `facing entity @p[tag=kitpvp.bw_cur] eyes` 再往前推**的（不是吐出那一刻定死方向），所以会拐弯追人。`bw_cur` 由 `babywhelp_ball` 每刻重建，用火球自己的 `kitpvp.bw_owner`（吐的时候从宝宝抄过来的 etid）排除召唤者，同样排除创造 / 旁观 / 观战。
- **命中半径 1.7，不是 1.5 也不是 2.2**：火球飞在目标眼高，而 `distance` 量的是火球到玩家**脚底坐标**的距离，垂直差恒约 1.62 ⇒ `..1.5` 永远差一点点（火球穿人而过还绕圈），`..2.2` 又会在水平 1.5 格外提前炸（看着像"提前引爆"）。`..1.7` 换算成水平约 0.5 格，正好贴到人。
- 命中后 `babywhelp_hit`：3 点 `minecraft:magic` 伤害（`by` 那只宝宝，宝宝已死则退化成无来源）+ `minecraft:explosion` 粒子与音效。**不点燃**：玩家数据不允许 `/data` 修改，`setblock fire` 会留火蔓延，所以只用火焰粒子表现。
- ⚠ `/damage` 的 target 只收**单个**实体（`EntityArgument.entity`），写成 `damage @a[...] 4 …` 会让整个 `.mcfunction` 解析失败、整文件不注册（表现为"没伤害、日志里 `Failed to load function … 只允许一个实体，但提供的选择器允许多个实体`"）。正确写法 `as @a[...] run damage @s 4 minecraft:magic`。
- 撞方块或飞满 40 刻（约 16 格）走 `babywhelp_fizzle`：只冒烟，不放火、不改方块。
- 寿命用实体分数 `kitpvp.bw_life`（每刻 +1，40 刻熄）。实体分数同样是"分数不存在就不匹配"，所以 objective 必须在 `load.mcfunction` 里 add，且不要在没 `/reload` 的环境里指望它。

## 3. 共通机制

**召唤链**：kit 68 的山羊刷怪蛋 → `earth_used` 计数 > `earth_last` → `skill/earth/cast`（首行 `operation last = used`）→ 在载体山羊位置调 `skill/earth/summon` → `random` → `link` → 首次召唤设冷却 + actionbar 播报。

**归属与同队**：`skill/earth/link.mcfunction` 给召唤物写 `kitpvp.earth_owner = 主人的 etid`，并把主人和召唤物一起 `team join earth_1..6`。同队 ⇒ 召唤物不打召唤者。**单人测试看不到"打人效果"就是这个原因**。

**清场**：`game/reset.mcfunction:60` 按 `kitpvp.earth_minion`（本体）与 `kitpvp.earth_mount`（船 / 矿车 / 熊）清，`/kill` 走 discard、无视 `Invulnerable`；守卫类 marker（木星 / 动员家）必须排在前面清。

**三种"战斗触发"**：

| 方式 | 适用 | 坑 |
|---|---|---|
| advancement `entity_hurt_player` + `source_entity.nbt` | 想精确知道"谁打的" | 这个版本上一直没触发过（已弃用） |
| `@a[nbt={HurtTime:9s}]` + N 格内找召唤物 | 打中后施加效果 | 别人打的也算（会误判） |
| `@e[nbt={Health:0.0f}]` | 死亡瞬间 | 自然死亡才行，`kill` 的 discard 不触发；木星实测连尸体帧都抓不到 |

**四个反复踩的坑**：
1. `scores={kitpvp.X=..0}` 在**分数不存在**时对任何实体都不成立 ⇒ 召唤时必须 `scoreboard players set` 埋初值；拿计分当门槛（如出生宽限）尤其脆，能换成 tag 就换。
2. 同一刻先 `kill` 再 `summon` 同一个写死 UUID ⇒ `addFreshEntity` 静默拒绝。
3. `schedule` 出来的函数**没有位置上下文**；`tick` 派发也没有 ⇒ 要么 `execute at` 明确给位置，要么留 marker 锚点（但飞行器不能用 marker，会丢朝向）。
4. `dx/dy/dz` 只收 double，**不收范围**（`dy=6..` 会让整个函数不注册）。范围只能写在 `distance`/`scores`/`x_rotation` 上。
5. **`etid` 的 0 不是“第 0 号玩家”，而是“还没分到槽位”**（`link.mcfunction` 选槽前它一直是 0）。拿“召唤物 owner == 玩家 etid”来排除召唤者时，必须先要求 owner ≥ 1，否则无主召唤物 + 未分配玩家会双双取 0 而互相“认亲”，把人全排除掉。`gearbox_aura`、`venus_chill_mark`、`flyer_tick` 都踩过这个坑。
