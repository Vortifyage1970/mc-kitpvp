# KitPvP 项目设计文档

> **定位**：本文件是**设计意图与规则**的唯一依据——描述"玩家体验到什么"，不描述"代码怎么写"。
> 任何与本文档冲突的实现方案，以本文档为准。
>
> **收录判据（硬性）**：一条信息只要在"新增一个职业 / 一个技能"时必须被修改，就**不属于**本文件。
>
> 本文件只在**改了游戏规则**时才动：加一条判定、改一次胜利条件、调一次时间、改一次分类配额。
> "又做完一个职业"不该碰它。

## 二、通用规则

### 2.1 数据包加载

- 按需设置 gamerule
- 创建所有计分板、队伍、标签
- 所有玩家状态归零
- 不强制传送、不改时间天气（由"开局"处理）

### 2.2 主大厅流程

1. 玩家进入 → 传送到大厅，冒险模式，清空背包
2. 在大厅自由走动
3. 选择职业：查看职业介绍 → 聊天栏点击确认
4. 随机职业：点"随机"按钮，从可用职业池随机
5. 选择地图：从已注册地图中选，也可随机
6. 按下开始按钮：所有人就绪后触发 `game/start`

### 2.3 职业选择界面

每个职业在选择时，聊天栏统一显示（缺项标"—"）：

```
┌──────────────────────────────
│ 职业名：战士
│ 分类：经典（表）
│ 简介：铁甲冲锋的正面战士
│ 武器单次伤害：6（悬停查看详情）
│ 武器攻击速度：1.6
│ 总护甲值：15
│ 总护甲韧性：0
│ 头盔：铁头盔
│ 胸甲：铁胸甲
│ 护腿：铁护腿
│ 靴子：铁靴子
│ 物品：熟牛排 x24、金苹果 x2
│ 被动：开局具有 2 个金苹果
│ 技能：无
│ 命数：3
└──────────────────────────────
[ 确认选择 ]  [ 返回 ]
```

各行的取值必须与 `kit/<职业>.mcfunction` 一致：伤害/攻速是**实际生效**的数值（含 `AttributeModifiers` 覆盖、附魔加成），护甲/韧性含各件护甲自带的数值。

悬停预览（`show_item`）与数值文字（`show_text`）分工：

- 武器数字 → `show_item` 预览真实武器（含 `Enchantments` / `AttributeModifiers` 等 NBT），与源码逐字一致
- "（悬停查看详情）" → `show_text` 列出 武器 / 单次伤害 / 攻击速度 / 附魔，保证数值一定看得到
- 四个护甲槽与"物品"行的每一件物品 → 各自 `show_item` 预览

卡片的 9 份 `.mcfunction` 由 `tools/gen_cards.py` 生成，改数值时改脚本再重跑，别手改。

参照实现：`kit/info/*.mcfunction`。

点击"确认选择"后 → 设 `kit` 分 → 发放装备 → 聊天栏提示"已选择战士"。

### 2.5 重合职业处理

允许多人选同一职业。每个玩家独立计算状态：

- 不共享冷却、不共享物品、不共享效果
- 检测必须保证多人同一职业不会出现重叠
- 涉及召唤物、衍生物的职业，每个召唤物必须绑定到拥有者，不能让召唤物与召唤者敌对

### 2.6 开局

1. 所有人传送到地图，在多个重生点中抽取
2. 在各自落点设置 `spawnpoint`
3. 冒险模式切换为生存模式
4. 每人获得 5 秒无敌
5. 标题提示"游戏开始"，播放音效
6. 8 分钟倒计时开始

### 2.7 命数与重生

- 默认每人 3 条命
- 部分职业命数特殊
- 部分职业有"死亡不计"的机制
- 死亡后：
  - 命数 -1
  - 传送回自己的重生点
  - 5 秒无敌
  - 保留背包，仍使用选职业时发放的装备
- 重生点被水或方块占住时，原版会判定重生点无效、把人丢到主世界出生点（主大厅）。
  兜底：分配出生点时在该点留一个隐形 marker 锚点，`player/after_death` 按 `kitpvp.spawn_slot`
  把玩家 `tp` 回自己的锚点（见 `04-hazards-reminder.md` §十一）。
- 命数归 0 → 进入旁观模式

### 2.8 战斗规则

- 无阵营，所有人互为敌人
- 允许有限度放置 / 破坏方块（不破坏平衡为前提）
- 大部分装备无法破坏（`Unbreakable:1b`）
- 食物受限：每个职业食物种类和数量不同
- 死亡不掉落

### 2.9 特殊物品与地形

**瞬移类物品**（紫颂果、末影珍珠等）：

- 允许使用，但需考虑穿墙、卡位、掉出地图
- 边界外掉落 → 判定为死亡（扣命数）
- 不应导致"卡在虚空不死"的状态

**虚空地图**：

- 无护栏、下方即虚空的地图必须有兜底机制
- 玩家 Y 坐标低于阈值时触发死亡判定

### 2.10 突然死亡（8 分钟后）

- 触发条件：开局满 8 分钟（可配置）
- 效果：给所有存活玩家一个一次性技能物品，间隔按**剩余命数**分档——**3 命 45 秒 / 2 命 35 秒 / 1 命 25 秒**
  （命少的拿得更快，用来加速收尾）
- 节奏：进入突然死亡的当刻先发一颗，之后按上述间隔循环；掉命当刻就按新间隔收紧倒计时，
  不需要把旧的（更长的）间隔走完
- 物品类型：对应各职业的"魂石"（如战士的魂石、弓箭手的魂石、地球的魂石）
- 一次性：使用后消失，下次刷新再给
- 目的：加速比赛进程

### 2.11 胜利与重置

结束条件：

- **胜利**：仅剩 1 名玩家命数 > 0 → 该玩家获胜。
- **平局**：幸存者降为 0，且场上还有在线旁观者（仍有人在看，说明不是全员掉线）→ 按平局结算。
- 全员掉线（0 幸存者且无在线旁观者）**不结算**，避免误清场；debug 模式（`#debug=1`）下也不自动结算。

结算流程：

1. 宣布胜利者／平局（title + 音效）
2. **封锁 10 秒**：全体给抗性 V（100% 减伤），避免结算期间还有人被打死
3. 等待 10 秒
4. 所有人初始化（清背包、清分数、清 tag、清队伍）
5. 传送回主大厅
6. 清除我们生成的实体：
   - 清除：掉落物、召唤物（幽灵魂石的阴兵）
   - 不清除：玩家、画、物品展示框、永久装饰实体
   - 约定：每新增一种召唤物，就在 `game/reset` 的清理列表补一行
7. 尽可能复原地图（方块回滚）
8. 重置完成 → 回到"主大厅流程"第 1 步

### 2.12 地图

- 每张地图有独立特性（地形、边界、特殊机制）
- 地图信息记录在单独的注册表里
- 支持多个默认出生点有效随机重生

### 2.13 令牌类技能的冷却口径

- 令牌类主动技能的"施法按钮"是**消耗品**（刷怪蛋 / 投掷物 / 弹药）。`cd` **不代表"用"的间隔**，只用来限制补货。
- 补货规则 = 持有上限（到上限就不再补）＋ 补货间隔。**用掉一个就从那一刻开始计时**：
  满仓时用掉一个，也必须等满一个间隔才补回来，**不能当场补**。
- 计时中再用**不重置**（`cd<=0` 守卫），所以连续出手不会把补货越推越远。
- 已按此口径实现：**纵火狂燃烧瓶、末影人末影之珠、里·弓箭手炮台令牌、狼人嗅闻令牌、驯兽师狼蛋、文明小子口水、李朱俊泽 iLsacuL 召唤蛋、地球召唤生灵蛋**。
- 例外（"真冷却"，效果期与冷却期共用同一个 `cd`）：坦克举盾、刺客隐匿、渔夫寻回三叉戟、海盗换弹、里·弓箭手熔火核心。
  这些技能的冷却即技能本身的使用间隔，其中渔夫 / 海盗的冷却还兼作令牌 / 弹药的补发闸门。
- 另一类例外（**两把锁互锁**）：里·渔夫的两个技能（术式顺转·「苍」/ 领域展开）用 `cd` 与 `cd2` 分别代表两个技能自身，
  但**放任何一个都会把两个一起锁住**，锁定时长 = 施放的那个技能自己的冷却（苍 → 两个都锁 45 秒；领域展开 → 两个都锁 240 秒）。
  前摇期间先用 `cd` / `cd2` 占位（30 刻 / 20 刻），释放时再改写成真冷却，这样"按两次"不会叠出第二发。
  另外**手上同时只有一个令牌**：放技能的那一刻把另一个技能的令牌 `clear` 掉，两个冷却都归零后由 tick 一次性发回。
  发回的触发是"**刚放过技能**"（`cang_release` / `domain_open` 打开 `kitpvp.tainted_fisher_handout` 窗口，`handout` 发完关窗），
  **不是"背包里没有"** —— 后者会让拖动物品 / 丢地上 / 塞箱子都凭空多出一个（04 §四）。
- 第三类例外（**自愈式补货**，太阳的两个令牌与药剂师的技能组 1）：太阳两个技能各走各的冷却（耀斑 `cd` 15 秒 / 黑子 `cd2` 40 秒），
  令牌在"**冷却走完 + 手上没有 + 地上也没有**"时补一颗（`skill/sun/refill_flare` / `refill_spot`，tick 每刻调用，只在 `#state=1`）。
  与上一类的区别：窗口模型把补发绑在"**刚放过技能**"上，只在玩家按冷却正常循环时才成立；
  太阳改成自愈，为的是让**非施法路径**的丢失（丢地上 / 被偷 / 背包满掉地上）也能回来——那正是"耀斑有时不补充"的成因。
  **已接受的漏洞**：玩家故意把令牌丢在远处能提前拿回一颗；但施法仍被冷却闸门拦着（多发一颗换不到额外一发），
  且地上已有同类令牌时不补，"丢一颗换一颗"没有净收益。里·渔夫维持互锁 + 窗口不变。
  药剂师的技能组 1 是**四瓶一套**：投出任意一瓶即收走整套并进 30 秒冷却，冷却走完按同一套自愈口径补满
  （`skill/alchemist/refill_splash`，tick 每刻调用，只在 `#state=1`）。
  里·驯兽师同属这一类，但按两套蛋各走一条冷却：技能组 1（三枚，`cd` 35 秒）、技能组 2（四枚，`cd2` 60 秒），
  任一枚用掉即整套收走，冷却走完由 `skill/tainted_tamer/refill1` / `refill2` 补满。
- 第四类（**每条命一次**）：药剂师的技能组 2 不占 `cd`，用 tag `kitpvp.alchemist_elixir_used` 表达"本命已经用过"；
  喝下一瓶即收走其余三瓶，直到死亡重生才解锁并补满（`player/after_death` → `skill/alchemist/restock_elixir`）。

## 三、职业模板

写每个职业时按模板填。没写的项按默认值处理。

**本模板是"怎么填"，不是"填了什么"。填好的实例放 `06-kit-registry.md`。**

```yaml
职业名: 战士
分类: 经典（表）
简介: 铁甲冲锋的正面战士

装备:
  头盔: minecraft:iron_helmet
  胸甲: minecraft:iron_chestplate
  护腿: minecraft:iron_leggings
  靴子: minecraft:iron_boots
  主手: minecraft:iron_sword
  副手: 无
  食物: minecraft:cooked_beef x 16
       minecraft:golden_apple x 2

属性:
  最大生命: 20
  移动速度: 0.1
  攻击力: 1
  护甲: 15
  护甲韧性: 0
  永久效果: 无

被动: 无

技能: 无

命数: 3
特殊: 无
```

**复用语法**：如果某职业和另一个职业大部分相同，只写差异：

```yaml
职业名: 某职业
分类: 某分类
继承: 某职业
技能:
  名称: 某技能
  冷却: 60 秒
  效果: ...
命数: 5
```

## 六、维护契约

> 本节回答一个问题：**下次加东西时，我该动哪个文件。**
> 目的是让本文件不再因为"又做了一个职业"而膨胀。

### 6.1 什么放哪

| 信息 | 放哪 |
|---|---|
| 版本红线、禁止语法 | `00` |
| 函数 / 文件清单 | `01`（扫描生成，不手写） |
| 命令语法、易错写法 | `02` |
| 玩家体验、判定、时间、胜利条件、分类配额、模板 | `03` |
| 坑位、约定、已踩过的错 | `04` |
| 技能实现模板（主动 / 自动 / 投掷） | `05` |
| 职业编号、分类归属、状态、职业卡片 | `06` |
| objective / tag / 物品标记 的实际占用 | `07` |

### 6.2 加东西时动什么

**加一个职业：**

1. `06` 总表加一行（编号按 `06` §一 的分类号段顺延，不跳块）
2. `06` 卡片加一节
3. `kit/<职业>.mcfunction`（发装备）+ `util/give_kit.mcfunction` + `skill/dispatch.mcfunction` 同步编号
4. 随机池：`kit/random.mcfunction`（全职业池）与本职业所属的分类池
   （`kit/random_classic.mcfunction` = 表池 / `kit/random_tainted.mcfunction` = 里池），
   各自改 `#pool_size` 并在末尾追加一行"序号 → 编号"映射（编号不连续时全靠这行进池）
5. `kit/list/<分类>.mcfunction` 加一行菜单项，位置按编号顺序
6. 建 `skill/<职业>/` 文件夹，被动放 `skill/<职业>/passive`（见 `05` 第零节）
7. 若占用了新的 objective / tag / 物品标记 → `07` 补行
8. **不碰 `03`**

**加一条规则**（改命数上限、改倒计时、改胜利条件、改分类配额）：

- 只改 `03`
- 改完检查 `06` / `07` 里有没有需要跟进的实例

**改一个职业的数值：**

- 改 `06` 卡片 + 对应 `kit/*.mcfunction`
- 不动 `03`

**加一个新技能：**

- 放 `skill/<职业>/<动作>.mcfunction`（动作名见 `05` 第零节；**不要**平铺在 `skill/` 根下）
- 按 `05` 的模板选类型实现
- `07` 补 objective / tag / 物品标记
- 若产生了新的通用坑位 → 补 `04`
- 只有"规则本身变了"才动 `03`

**得到新的经验，如经测试可用的advancement策略、函数逻辑：**

- 加入到 `02` 的经验清单中

**加入新的召唤物**
- 置于summon\文件夹中，方便后续调用

### 6.3 派生文件的权威顺序

`01` 与 `07` 是**账本**，代码是**事实**。二者冲突时：

- **以代码为准**，修正账本。
- 账本允许暂时滞后，但**不允许写与代码相反的内容**。
- 这条约定是刻意的：它免除"每次改代码必须同步文档"的负担，只要求在**发现不一致时**修账本。

### 6.4 编号铁律

职业编号只增不复用。编号一旦发出，就是该职业的永久身份；职业被删除，编号作废，不还给后来者。
详见 `06-kit-registry.md` 第一节。

- 魂石注册表（每加一个职业的魂石就改一次）
